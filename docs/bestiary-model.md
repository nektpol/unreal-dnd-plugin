# Bestiary model

`FDnd5eCreature` is a Blueprint-visible value in the `Dnd5e` module. The creature header uses the shared record identity and provenance model. Size, creature type, and alignment use the existing size enum and Gameplay Tag vocabulary.

| Field | C++ type | Meaning |
| --- | --- | --- |
| Header | `FDnd5eRecordHeader` | Display name, record identity, and provenance. |
| Sizes | `TArray<EDnd5eSize>` | Ordered size choices. |
| CreatureType and CreatureSubtypes | `FGameplayTag`, `TArray<FDnd5eCreatureSubtype>` | Single creature type and ordered subtype values with name, optional prefix, and a hidden-prefix flag. Read `Name` for the original subtype term. |
| CreatureTypeChoices | `TArray<FGameplayTag>` | Ordered alternatives. The single type is unset for a choice. |
| Alignment | `FGameplayTagContainer` | Tags for an explicit simple alignment. |
| bHasAlignment and AlignmentOptions | `bool`, `TArray<FDnd5eCreatureAlignmentOption>` | Authored field presence and ordered options. Each option retains its `TArray<FString> Codes`, optional chance, note, and special text. |
| ArmorClasses | `TArray<FDnd5eCreatureArmorClass>` | Ordered numeric or special AC entries. Each holds `bool bHasValue`, `int32 Value`, `TArray<FDnd5eContentBlock> Sources`, `TArray<FDnd5eInlineContent>` for each of `Condition` and `Special`, and `bool bWrapInParentheses`. |
| ArmorClassPresence | `EDnd5eValuePresence` | Distinguishes omitted, null, and present AC arrays. |
| HitPoints | `FDnd5eCreatureHitPoints` | Field presence, printed average and dice formula, or special text in `TArray<FDnd5eInlineContent> Special`. Check `bHasAverage` before reading the numeric value. |
| WalkSpeed | `FDnd5eDistance` | Convenience projection of the top-level walking distance, including authored zero. |
| Movement | `FDnd5eCreatureMovement` | Presence, standard and alternate speeds with conditions, hover, and ordered choice modes with a shared distance and note. |
| AbilityScores | `FDnd5eCreatureAbilityScores` | Six named `int32` ability scores. Check `bHasScores` before using them. All six keys may be omitted. If any key is supplied, the reader requires the complete set. |
| Skills | `TArray<FDnd5eCreatureSkillBonus>` | Skill name and either a signed integer with `bHasNumericBonus` or authored text in `BonusExpression`. |
| SkillChoices | `TArray<FDnd5eCreatureSkillChoice>` | Ordered choice groups. Each contains one-of options in `TArray<FDnd5eCreatureSkillBonus>`. |
| Senses and Languages | `TArray<FString>` each | Authored senses and languages. |
| PassivePerception | `int32` | Printed numeric passive Perception. |
| PassivePerceptionPresence and PassivePerceptionFormula | `EDnd5eValuePresence`, `FString` | Distinguish omitted, null, numeric, and authored formula values. |
| ChallengeRating | `FDnd5eCreatureChallengeRating` | Presence, authored base, lair and coven CR strings, and optional base and lair XP overrides. Use `ChallengeRating.Base` to read the base string. |
| Traits, Actions, BonusActions | `TArray<FDnd5eCreatureEntry>` each | Ordered named entries. Each entry holds a name and `TArray<FDnd5eContentBlock> Entries`. |

Integer members default to zero. Arrays, strings, and tag containers default to empty. The model currently provides the initial stat-block representation. The native `FDnd5eJsonCreatureReader::ReadCreature` reads a selected direct row from a supplied `monster` document by exact authored name and source. It maps all 14 native creature types from a string or an object with a string type and optional plain or prefixed subtypes. The initial stat-block conversion supports numeric, sourced, conditional, and special AC entries, signed and compound saving throw and skill bonuses, one-of skill choices, and separate trait, action, bonus action, reaction, legendary action, and mythic action groups. Reaction, legendary, and mythic arrays distinguish missing, null, and present entries. Their headers are read independently as content blocks. Standard and lair legendary action counts each have a presence flag, including when the supplied count is zero. Numeric source page zero leaves the page unspecified. Text page references are retained. Failure returns diagnostics and an empty creature. Use the native `FDnd5eJsonCreatureReader::ReadDocuments` batch API for typed copy results. It returns successful direct and assembled creatures in input document and row order, together with per-document and per-row diagnostics. One batch uses a single dataset namespace and can supply a template document. A successful document envelope can contain failed rows, and the batch can return other successful creatures. Field-shape inventory is available through the audit API. The native `FDnd5eCreatureCatalog` stores typed records in publication order and looks them up by exact record ID. Queries combine optional namespace, primary source, case-insensitive display name, and creature type filters. Type filtering includes authored type choices. Catalog replacement validates identities and primary sources before publishing the new records. A duplicate or invalid record leaves the active catalog available. The native `FDnd5eJsonCreatureCatalogLoader::LoadCatalog` reads the local Bestiary `index.json` under the supplied dataset root and can read a separately selected template file. It loads each indexed file once in filename order and publishes after the batch and catalog checks pass. File and catalog diagnostics are returned separately from document and row diagnostics. A failed load leaves the active catalog available. Blueprints can hold a transient `UDnd5eCreatureCatalogObject` and load it with `Load Creature Catalog`. Query and exact lookup delegate to the native catalog. The Blueprint result reports the published count and combines loader, document, and row diagnostics while retaining their origin and severity. In Unreal Editor, **Tools > Dnd5e Bestiary Dataset Settings** remembers the local dataset directory, dataset namespace, and optional template and lore files per user and project. **Tools > Load Dnd5e Bestiary Dataset** publishes the successful load to the current editor session and reports diagnostics in the **Dnd5e Dataset** Message Log. A failed reload keeps the active catalog. The catalog lives in memory for the editor session and can be loaded again from the saved settings after restart. **Tools > Dnd5e Bestiary Browser** opens the editor's current catalog. The list filters by creature name or displayed source and retrieves the selected creature by exact record ID. It refreshes on successful publication. The read-only Stat Block previews typed classification and alignment, numeric and special AC and HP, primary and alternate movement, ability scores and display modifiers, saving throws, skills, grouped defenses, senses, languages, challenge rating, spellcasting, and action groups. It displays authored zeroes when present and omits hidden spellcasting groups and entries. The card groups classification, vitals, a six-cell ability grid, and combat facts above separately headed action and spellcasting sections. The text within each section uses the bounded Content preview. Recognized legacy and revised attack, saving throw, and outcome labels retain their source tokens and render as readable labels alongside existing roll annotations. The preview displays preserved unsupported text fragments when an explicit display value is absent. Changing selection clears the previous card and returns the scroll position to the top. An optional local lore file contributes direct `monsterFluff` text to `SupplementaryContent.Entries` by exact dataset namespace, authored name, and source. Matched copy rows produce a warning. The loader preserves the contributing row provenance and publishes only after the requested lore validates. Inherited lore, the Info view, and media are pending.

See [Shared models](shared-models.md) for record, measurement, dice, and Content definitions.

### Document audit

`FDnd5eJsonCreatureReader::AuditDocument` parses one supplied document and visits every row. The result separates document diagnostics from row status, diagnostics, and raw field shapes. Field shapes include JSON type and exact pointer, with array indices grouped under a shared path. The inventory captures top-level fields and descends up to four levels below each field. Successful row conversion can still leave fields or inline content outside the initial reader scope.

`AuditDocuments` resolves basic copies across a batch of documents in one dataset namespace. Name and source are matched case-insensitively. The resolver applies whole-field inheritance, explicit clears, and preserve flags. The resolver applies append, prepend, replacement by name, and removal by name to trait, action, and bonus action arrays. A string remove directive clears the entire field. Wildcard text replacement supports global ICU regex substitutions, optional entry property selection, and inline tag protection. The `replaceTxt` modifier also accepts named entry and header fields. It rewrites only the selected field and treats an absent or null field as a no-op. Named field operations run before wildcard replacements. The `scalarAddHit` and `scalarAddDc` modifiers adjust numeric inline tags within named trait, action, bonus, reaction, legendary, mythic, variant, and spellcasting fields. These fields also accept the whole-field `remove` directive. The single-document reader and audit continue to report copy rows as unsupported.

The two-argument `AuditDocuments` overload accepts a separate template document in the same dataset namespace. The resolver looks up each `_templates` reference by name and source. Template root values can replace inherited values, while keys authored on the copy row, including explicit nulls, take precedence. Later templates can replace earlier template root values. For each modifier field, the copy row's operations run first, followed by template operations in reference order. The resolver supports duplicate-safe appends on languages, resistances, vulnerabilities, damage immunities, condition immunities, and miscellaneous tags. It compares each candidate with the array before the operation. The root modifier addSenses adds missing senses and raises lower ranges in canonical sense strings. The root modifier `addSkills` computes skill bonuses from the assembled ability scores and base challenge rating. It preserves higher numeric bonuses and compound bonus expressions. Languages, senses, saving throw bonuses, and skill bonuses are exposed on the typed creature. Saving throws use native ability tags and are returned in ability order. Their presence distinguishes a missing property, explicit null, and an authored object. The root modifier `replaceSpells` replaces exact spell strings in level-based and daily lists on the first spellcasting block. It sorts the edited list case-insensitively and preserves level metadata. The root modifier `addSpells` appends level-based, daily, and at-will spells to the first block. It preserves duplicates and existing level metadata, and sorts an existing level list after appending. The root modifier `removeSpells` removes all exact string matches from daily and level-based lists on the first spellcasting block. It preserves the remaining order and level metadata. The `scalarAddProp` and `scalarMultProp` modifiers update numeric properties on HP, save, and skill objects. They preserve JSON numbers and signed bonus strings in their original types. Multiplication can round down, and compound bonus expressions defer the copy. The `appendArr` modifier can append a complete spellcasting block. Root `setProp` assigns a top-level property and clears the field when the authored value is null. Dotted paths and edits to identity or copy metadata remain deferred. Root `maxSize` keeps ordinary sizes at or below the cap in ascending order and uses the cap if none remain. Root `scalarMultXp` scales positive explicit XP or looks up standard base XP and preserves alternate challenge rating metadata. A zero or missing explicit value falls back to standard XP. Results must fit the typed integer XP field after optional flooring. The HP `prefixSuffixStringProp` modifier wraps the stored formula text while preserving the adjusted average. The `insertArr` modifier inserts into an existing trait, action, or bonus array using an integer index. The `removeArr` modifier accepts literal string selectors and removes one exact occurrence per selector. Defense arrays accept plain append and removal operations, and reaction arrays accept appends. The typed creature exposes damage vulnerabilities, resistances, immunities, and condition immunities. Each list distinguishes absence, explicit null, and an authored array. Entries preserve source order in depth-first order, with parent indices linking group children. Groups carry qualifiers and notes. Special text is parsed into inlines. Plain entries retain their source tokens, with native tags where available. The typed creature exposes spellcasting blocks after copy assembly. Blocks preserve authored ability and display tokens, headers, footers, item references, and hidden groups. Their lists preserve group and key, optional level and slot metadata, use count and per-spell use, and inline spell entries with individual hidden flags. Missing and explicit null spellcasting are distinct from an authored array. Miscellaneous tag changes are applied to the assembled JSON. Unsupported operations defer the copy. Template diagnostics carry the template file and JSON pointer, while unresolved references point to the copy row.
