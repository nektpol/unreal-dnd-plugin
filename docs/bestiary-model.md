# Bestiary model

`FDnd5eCreature` is a Blueprint-visible value in the `Dnd5e` module. The creature header uses the shared record identity and provenance model. Size, creature type, and alignment use the existing size enum and Gameplay Tag vocabulary.

| Field | C++ type | Meaning |
| --- | --- | --- |
| Header | `FDnd5eRecordHeader` | Display name, record identity, and provenance. |
| Sizes | `TArray<EDnd5eSize>` | Ordered size choices. |
| CreatureType and CreatureSubtypes | `FGameplayTag`, `TArray<FDnd5eCreatureSubtype>` | Single creature type and ordered subtype values with name, optional prefix, and a hidden-prefix flag. Read `Name` for the original subtype term. |
| CreatureTypeChoices | `TArray<FGameplayTag>` | Ordered alternatives. The single type is unset for a choice. |
| Alignment | `FGameplayTagContainer` | Tags for an explicit simple alignment. |
| bHasAlignment and AlignmentOptions | `bool`, `TArray<FDnd5eCreatureAlignmentOption>` | Authored field presence and ordered options. Each option retains its `TArray<FString> Codes`, optional chance, note, and special text. |
| ArmorClasses | `TArray<FDnd5eCreatureArmorClass>` | Ordered numeric or special AC entries. Each holds `bool bHasValue`, `int32 Value`, `TArray<FDnd5eContentBlock> Sources`, `TArray<FDnd5eInlineContent>` for each of `Condition` and `Special`, and `bool bWrapInParentheses`. |
| ArmorClassPresence | `EDnd5eValuePresence` | Distinguishes omitted, null, and present AC arrays. |
| HitPoints | `FDnd5eCreatureHitPoints` | Field presence, printed average and dice formula, or special text in `TArray<FDnd5eInlineContent> Special`. Check `bHasAverage` before reading the numeric value. |
| WalkSpeed | `FDnd5eDistance` | Convenience projection of the top-level walking distance, including authored zero. |
| Movement | `FDnd5eCreatureMovement` | Presence, standard and alternate speeds with conditions, hover, and ordered choice modes with a shared distance and note. |
| AbilityScores | `FDnd5eCreatureAbilityScores` | Six named `int32` ability scores. Check `bHasScores` before using them. All six keys may be omitted. If any key is supplied, the reader requires the complete set. |
| Skills | `TArray<FDnd5eCreatureSkillBonus>` | Skill name and either a signed integer with `bHasNumericBonus` or authored text in `BonusExpression`. |
| SkillChoices | `TArray<FDnd5eCreatureSkillChoice>` | Ordered choice groups. Each contains one-of options in `TArray<FDnd5eCreatureSkillBonus>`. |
| Senses and Languages | `TArray<FString>` each | Authored senses and languages. |
| PassivePerception | `int32` | Printed numeric passive Perception. |
| PassivePerceptionPresence and PassivePerceptionFormula | `EDnd5eValuePresence`, `FString` | Distinguish omitted, null, numeric, and authored formula values. |
| ChallengeRating | `FDnd5eCreatureChallengeRating` | Presence, authored base, lair and coven CR strings, and optional base and lair XP overrides. Use `ChallengeRating.Base` to read the base string. |
| Traits, Actions, BonusActions | `TArray<FDnd5eCreatureEntry>` each | Ordered named entries. Each entry holds a name and `TArray<FDnd5eContentBlock> Entries`. |

Integer members default to zero. Arrays, strings, and tag containers default to empty. The model currently provides the initial stat-block representation. The native `FDnd5eJsonCreatureReader::ReadCreature` reads a selected direct row from a supplied `monster` document by exact authored name and source. It maps all 14 native creature types from a string or an object with a string type and optional plain or prefixed subtypes. The initial stat-block conversion supports numeric, sourced, conditional, and special AC entries, signed and compound skill bonuses, one-of skill choices, and separate trait, action, and bonus action groups. Numeric source page zero leaves the page unspecified. Text page references are retained. Failure returns diagnostics and an empty creature. Selected copy rows require a future assembly step. Catalog lookup, supplementary lore and media, and editor browsing are pending.

See [Shared models](shared-models.md) for record, measurement, dice, and Content definitions.

### Document audit

`FDnd5eJsonCreatureReader::AuditDocument` parses one supplied document and visits every row. The result separates document diagnostics from row status, diagnostics, and raw field shapes. Field shapes include JSON type and exact pointer, with array indices grouped under a shared path. The inventory captures top-level fields and descends up to four levels below each field. Successful row conversion can still leave fields or inline content outside the initial reader scope.

`AuditDocuments` resolves basic copies across a batch of documents in one dataset namespace. Name and source are matched case-insensitively. The resolver applies whole-field inheritance, explicit clears, and preserve flags. The resolver applies append, prepend, replacement by name, and removal by name to trait, action, and bonus action arrays. A string remove directive clears the entire field. Wildcard text replacement supports global ICU regex substitutions, optional entry property selection, and inline tag protection. The `replaceTxt` modifier also accepts named entry and header fields. It rewrites only the selected field and treats an absent or null field as a no-op. Named field operations run before wildcard replacements. The `scalarAddHit` and `scalarAddDc` modifiers adjust numeric inline tags within named trait, action, bonus, reaction, legendary, mythic, variant, and spellcasting fields. These fields also accept the whole-field `remove` directive. The single-document reader and audit continue to report copy rows as unsupported.

The two-argument `AuditDocuments` overload accepts a separate template document in the same dataset namespace. The resolver looks up each `_templates` reference by name and source. Template root values can replace inherited values, while keys authored on the copy row, including explicit nulls, take precedence. Later templates can replace earlier template root values. For each modifier field, the copy row's operations run first, followed by template operations in reference order. The resolver supports duplicate-safe appends on languages, resistances, vulnerabilities, damage immunities, condition immunities, and miscellaneous tags. It compares each candidate with the array before the operation. The root modifier addSenses adds missing senses and raises lower ranges in canonical sense strings. The root modifier `addSkills` computes skill bonuses from the assembled ability scores and base challenge rating. It preserves higher numeric bonuses and compound bonus expressions. Languages, senses, and skill bonuses are exposed on the typed creature. The root modifier `replaceSpells` replaces exact spell strings in level-based and daily lists on the first spellcasting block. It sorts the edited list case-insensitively and preserves level metadata. The root modifier `addSpells` appends level-based, daily, and at-will spells to the first block. It preserves duplicates and existing level metadata, and sorts an existing level list after appending. The root modifier `removeSpells` removes all exact string matches from daily and level-based lists on the first spellcasting block. It preserves the remaining order and level metadata. The `scalarAddProp` and `scalarMultProp` modifiers update numeric properties on HP, save, and skill objects. They preserve JSON numbers and signed bonus strings in their original types. Multiplication can round down, and compound bonus expressions defer the copy. The `appendArr` modifier can append a complete spellcasting block. Spellcasting, defense, and miscellaneous tag changes are applied to the assembled JSON. Unsupported operations defer the copy. Template diagnostics carry the template file and JSON pointer, while unresolved references point to the copy row.
